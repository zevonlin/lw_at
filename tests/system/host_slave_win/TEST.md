# host_slave_win：主机与从机双线程测试

本目录模拟**一台主机设备与一台从机设备**经字节链路进行异步通信。重点不是在从机进程内部再开多线程去抢同一把锁，而是让两端各自拥有独立的调度上下文：主机决定何时发送、何时读取应答；从机线程循环执行 `feed` / `process`（定时器到期回调由从机线程轮询触发）。

```text
主线程（主机角色）
        | 写入下行字节
        v
   下行字节队列  ----读---->  从机线程（仅此线程调用 lw_at_*）
        ^                         |
        |                         | 经 Port.write 写出应答
        | 读取上行字节             v
   上行字节队列  <-----------------+
```

## 如何运行

```bash
cd lw_at/tests/system/host_slave_win
make run
```

需要 Windows 环境与 `gcc`。Makefile 强制开启透传编译选项。进程退出码为 0 表示全部检查通过。

场景编号、命令约定、能力边界与完整矩阵见同目录 [PLAN.md](PLAN.md)。若关注从机内部「空闲是否到期才允许 process」的细粒度步骤，见 `async_script`。若关注设置参数拆分的完整字符表，见 `lw_at_core`。若仅需单线程快速回归主路径，见 `host`。

## 与真实环境的对应关系

| 真实环境 | 本目录的实现方式 | 覆盖程度 |
| --- | --- | --- |
| 主机与从机各自调度 | 主机逻辑运行在主线程；从机逻辑运行在 `CreateThread` 创建的线程 | 覆盖 |
| UART 字节 FIFO | 双向环形字节队列 | 覆盖 |
| 主机在未收到 `OK` 时继续发送后续命令 | 主机连续写入下行队列，稍后再统一收集上行应答 | 覆盖（本目录重点） |
| 线路上的分片发送、偶发丢字节 | 可选的链路损伤处理（`link_impair`）：按固定块大小切分、丢弃指定字节、插入延迟或噪声 | 覆盖 |
| 从机空闲超时的精确边界 | 使用系统实时时钟与配置的 `idle_timeout_ms` | 覆盖较粗；需要逐步推进虚拟时间的细用例见 `async_script` |
| 从机正在执行 `process` 的函数体内部又被接收中断喂入新字节 | 从机线程内对库的调用是串行的，不插入这种抢占 | 不覆盖 |

约定：所有 `lw_at_*` API 只在从机线程中调用；主机线程只读写字节队列与测试辅助接口。

**与 `host_slave_send` 的分工**：本目录是双端**通测**（多业务命令、压力、损伤）。CIPMODE + CIPSEND 定长/流式进出、粘连丢载荷、应用 `data_exit`、溢出契约等专题见 [`../host_slave_send`](../host_slave_send/TEST.md)。本目录 `hs_cmd` **仅有无参流式** `CIPSEND`，不含定长 `CIPSEND=<len>`。

进入流式成功时的提示符为精确字节 `\r\nOK\r\n>\r\n`。

## 测试专用命令集

本目录使用自有命令表 `hs_cmd`（与例程命令表、以及其它测试目录中的 `AT+ECHO` 表分离），以便构造整数、字符串、慢处理、固定失败与透传等场景。

| 命令 | 用途 |
| --- | --- |
| `AT` | 联通性检查，成功回 `OK` |
| `AT+PING` | 先回中间信息行 `+PING:PONG`，再回 `OK`，用于验证中间信息与最终结果同时存在 |
| `AT+INT` | 整数的测试 / 查询 / 设置 / 执行（执行清零） |
| `AT+STR` | 字符串的测试 / 查询 / 设置 / 执行；覆盖引号与转义 |
| `AT+MIX` | 混合参数：整数、字符串，以及可选的第三整数槽（可为省略的参数槽） |
| `AT+MULTI` | 三个整数参数，便于连续发送导致多行粘连后核对最终保存值 |
| `AT+FAIL` | 固定返回失败，用于异常路径与恢复 |
| `AT+SLOW` | 在 handler 内主动延时一段时间再回 `OK`，用于验证从机仍在处理时主机已继续发送 |
| `AT+CIPMODE=<0\|1>` | 应用侧传输模式（非内核） |
| `AT+CIPSEND` | 无参：仅 `CIPMODE=1` 时进入流式透传（回 `\r\nOK\r\n>\r\n`） |

更完整的参数与回包约定见 [PLAN.md](PLAN.md) 第 2 节。

## 场景分组

下列字母为场景编号前缀，完整条目见 PLAN.md。

| 分组 | 覆盖内容 |
| --- | --- |
| N | 正常交互：联通、PING、整数、字符串、混合参数，以及「等待 OK 后再发下一条」 |
| P | 主机不等待应答即连发；从机慢处理时下行已堆积；一次写入多行完整命令 |
| I / K / F | 分片与不完整命令、完整行与尚未结束的不完整行粘连、仅有 `\r` 或仅有 `\n`、多余空行、行尾错误后的恢复 |
| C | 大小写错误、空行、引号参数、超长字符串、非法数字参数等 |
| G / X | 帧前/帧间噪声、丢字节、未知命令、固定失败命令 |
| B / R | 偏小接收缓冲导致溢出、下行队列满导致丢弃、主机侧慢读与读超时 |
| S | 大量连发、交替命令、按单字节切块、穿插慢处理等压力场景 |
| T | 流式透传数据分片、前静默不足的假 `+++`、较大载荷、透传期间误发 AT 文本 |
