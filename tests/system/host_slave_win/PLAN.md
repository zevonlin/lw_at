# host_slave_win 设计说明与场景清单

运行方法与目录级概述见 [TEST.md](TEST.md)。本文给出双端模型的设计约定、测试专用命令的语义、能力边界，以及完整场景编号表，供实现对照与后续增补场景时查阅。

## 1. 双端模型

本套件把「主机」与「从机」拆成两个调度上下文，中间只用字节队列相连，从而逼近现场「两端各自运行、经 UART 交换字节」的结构：

```text
主线程（主机角色）
        | 写入下行字节
        v
   下行字节队列  ----读---->  从机线程（仅此线程调用 lw_at_*）
        ^                         |
        |                         | 经 Port.write 写出应答
        | 读取上行字节             v
   上行字节队列  <-----------------+
```

| 真实环境 | 本模拟的对应方式 | 是否纳入本套件 |
| --- | --- | --- |
| 两台设备、两端各自调度 | 主线程执行主机逻辑；`CreateThread` 执行从机逻辑 | 是 |
| UART 字节 FIFO | `link_q` 环形字节队列（下行与上行各一条） | 是 |
| 主机在未收到 OK 时继续发送 | 主机连续写入下行，稍后再统一收集上行 | 是 |
| 线缆分片或发送变慢 | 主机主动分片写入，或经链路损伤处理（`link_impair`）按块切分并插入延迟 | 是 |
| 偶发丢字节或线路干扰 | 链路损伤处理（`link_impair`）丢弃指定位置字节，或在帧前/帧间插入噪声字节 | 是 |
| 从机空闲超时 | 系统实时时钟与配置项 `idle_timeout_ms` | 是；需要逐步推进虚拟时间的边界用例见 `async_script` |
| 从机 `process` 执行过程中又被接收中断喂入新字节 | 从机线程内对库的调用保持串行 | 否 |
| 硬件波特率不匹配、RTS/CTS 流控 | 不建模 | 否；必要时用分片、延迟、队列满近似部分现象 |

**线程约定**：所有 `lw_at_*` 接口只允许在从机线程中调用；主机线程只操作字节队列与测试辅助 API。

**协议约定（与库一致）**：命令行结束符仅为 `\r\n`。空闲定时器用于决定「何时允许开始处理已经完整的行」，**不是**行结束条件。因此，仅有 `\r`、仅有 `\n`、错误顺序的行尾，测例期望是不成帧、拼成脏行后回 `ERROR`，或暂时无应答，而不是「兼容任意终端行尾」。

## 2. 测试专用命令集 `hs_cmd`

为避免把产品例程命令表绑进双端压力与异常场景，本目录单独实现 `hs_cmd`，由从机启动时注册。命令内部状态仅由从机线程写入；主机侧若需核对从机保存值，应在场景结束、从机侧达到稳定点之后再调用查询接口，以避免竞态。

源文件：`hs_cmd.h` / `hs_cmd.c`。

### 2.1 命令一览

| 命令 | 支持的形态 | 作用 | 主要服务的测试目的 |
| --- | --- | --- | --- |
| `AT` | 执行 | 联通性检查，成功回 `OK` | 基线路径；压力场景中的仅作压力填充的简单命令 |
| `AT+PING` | 执行 | 先输出中间信息行 `+PING:PONG`，再回 `OK` | 验证中间信息与最终结果同时出现，以及上行粘连时的收集逻辑 |
| `AT+INT` | 测试 / 查询 / 设置 / 执行 | 有符号 32 位整数的范围说明、读写与清零 | 整数参数与四种命令形态 |
| `AT+STR` | 测试 / 查询 / 设置 / 执行 | 字符串读写；设置侧支持引号与转义 | 引号、转义、跨分片参数 |
| `AT+MIX` | 设置 / 查询 | `=<int>,<str>[,<opt_int>]`；第三参数槽允许省略 | 多个参数槽、省略参数槽、整数与字符串混合 |
| `AT+MULTI` | 设置 | 连续三个整数参数 | 多整型参数；连续发送导致多行粘连后核对最终值 |
| `AT+FAIL` | 执行 / 设置 | 固定返回失败 | 异常路径以及 `ERROR` 之后的恢复 |
| `AT+SLOW` | 执行 | 在 handler 内延时一段时间再回 `OK` | 从机仍在处理时，主机已把后续命令写入下行队列 |
| `AT+CIPMODE` | 设置 | 应用侧 0/1，决定无参 CIPSEND 是否可进流式 | 透传前置配置 |
| `AT+CIPSEND` | 执行 | 无参且 CIPMODE=1 时请求进入流式；成功回 `\r\nOK\r\n>\r\n` | 双端流式进入、数据与退出 |

> 定长 `AT+CIPSEND=<len>`、CIPABORT、粘连丢载荷、应用 `data_exit` 等不在本套件；见 [`../host_slave_send/PLAN.md`](../host_slave_send/PLAN.md)。

### 2.2 参数与回包约定

- **INT**：设置参数为十进制有符号 32 位整数；无法解析为整数时回 `ERROR`。查询输出 `+INT:<n>`。测试形态输出范围说明（实现可为简写形式）。无参数执行形态将保存值清零。
- **STR**：内部保存缓冲长度固定（含结尾 `NUL`）；超出上限回 `ERROR`。查询输出已去除包围引号并完成转义还原后的正文。库已支持的引号内逗号、`\"`、`\\` 等写法均应可测。
- **MIX**：至少需要整数槽与字符串槽；第三整数槽可省略（空的参数槽）。第二槽缺失或整型非法时回 `ERROR`。查询行应能反映各槽内容以及第三槽是否存在。
- **MULTI**：三个槽均必须是可解析整数；任一槽失败则整条命令失败。
- **SLOW**：默认延时约 30ms，可通过测试辅助接口调整。用于构造「从机 handler 尚未返回，主机已继续发送」的并行压力。
- **FAIL**：无论执行还是设置形态，均回 `ERROR`。

主机侧断言应优先核对上行文本（中间信息行、`OK`、`ERROR` 的出现次数与顺序）。仅当需要确认从机内部已保存的状态值时，才在场景稳定后调用 `hs_cmd_*_get` 一类接口。

## 3. 测试辅助模块

| 模块 | 职责 |
| --- | --- |
| `link_q` | 下行 / 上行环形字节队列，模拟 UART FIFO |
| `link_impair` | 作用于下行的损伤：按块切分、丢字节、发送前延迟、帧前或帧间插入噪声。上行方向损伤由 `host_collect_impaired` 在主机收集侧模拟。 |
| `host_api` | 主机侧发送、应答收集、期望匹配，以及场景开始/结束时的状态复位（命令状态、队列内容等） |
| `slave_rt` | 从机线程生命周期；支持使用偏小的接收/行缓冲重新初始化；透传数据回调捕获 |

## 4. 现场现象与期望行为

本节按现场常见现象归类，说明在本库契约下的期望行为，以及测例应如何构造。完整编号见第 5 节。

### 4.1 多帧在同一次到达中粘连

| 现象 | 常见来源 | 从机期望行为 | 测例构造要点 |
| --- | --- | --- | --- |
| 多个完整行粘在一起 | 主机不等待 OK 连发；DMA 一次上报多行 | 一次 `process` 连续处理多条命令，产生多段最终结果 | 一次写入 `AT\r\nAT+PING\r\n` 这类内容 |
| 完整行后面还跟着尚未结束的不完整行 | 发送在第二命令中途被打断 | 先执行完整行；尚未结束的不完整行在空闲超时后作废并回 `ERROR` | 先写入完整行与尚未结束的命令片段，再补写剩余部分 |
| 不完整行之后改发另一条新命令 | 用户放弃未完成输入并重敲 | 残留不完整行空闲超时后作废回 `ERROR`（未超时则与新命令拼成脏行回 `ERROR`），标准命令均可在其后恢复 | 尚未结束的命令之后直接写入新的 `AT\r\n` |
| 上行多个 `OK` 或「中间信息 + OK」粘连 | 从机连续回写，主机一次读出 | 主机收集逻辑必须按行解析与计数，不能把整块缓冲当作单一结果 | 结合慢读、短读场景验证计数 |

### 4.2 一帧被拆到多次到达

| 现象 | 常见来源 | 从机期望行为 | 测例构造要点 |
| --- | --- | --- | --- |
| 命令名或参数区分多次到达 | 单字节中断或短 DMA | 在凑齐 `\r\n` 之前不执行该命令 | 将一行拆成多次写入 |
| `\r` 与 `\n` 分两次到达 | 极为常见 | 仅有 `\r` 时不成帧；空闲超时内补上 `\n` 后成帧；超时后残留作废回 `ERROR` | 两次写入之间可插入延时 |
| 未完成命令停顿超过空闲时间后再续传 | 人工输入停顿、主机调度间隙 | 空闲超时后半行作废回 `ERROR`，须重新发送完整命令 | 与「放弃未完成命令并改发新命令」对照 |

### 4.3 行尾变体

规范只承认 `\r\n`。下列写法用于验证**失败可诊断、失败可恢复**，不是为了放宽协议。

| 写法 | 期望方向 |
| --- | --- |
| 只有 `\r`，或只有 `\n`，或 `\n\r` 错序 | 不成正确帧，或形成脏行后回 `ERROR`；随后用标准 `\r\n` 命令应可恢复 |
| `\r\n\r\n`，或两命令之间多出空行 | 空行不额外产生 `OK`；合法命令的 `OK` 次数正确 |
| 丢掉 `\n` 后再发下一命令 | 残留与下一帧粘连形成脏行回 `ERROR`（若已空闲超时则残留先作废不再粘连），随后标准命令可恢复 |

### 4.4 其它高频问题

| 类别 | 现象 | 期望方向 |
| --- | --- | --- |
| 前缀与形态 | 小写 `at`、前导空白、缺少 `AT` 前缀、一行内塞多条命令 | 失败；确认后续标准命令可恢复 |
| 参数 | 未加引号却含逗号、超长字符串、转义残缺、省略参数槽的位置 | 按参数拆分与取参规则成功或失败；失败后可恢复 |
| 时序 | 主机不等待；慢处理时下行堆积 | 最终应答次数与状态正确 |
| 丢失与干扰 | 丢字节、噪声字节、高位字节行、**大规模随机乱码刷屏（G-06）**、**stuck-bit 连续重复字节（G-07）**、**上行方向被干扰（U 组）** | `ERROR` 或脏行/溢出丢弃后可恢复；上行受损不产生假应答 |
| 缓冲 | 接收环形缓冲区溢出、行缓冲过短 | `ERROR` 后，联通确认命令（如 `AT`）应仍可成功 |
| 透传 | 透传中发送看似 AT 的文本；前静默不足的 `+++`；合法退出后若仍有尚未结束的不完整行 | 透传数据进回调；合法退出后回到命令模式 |

### 4.5 明确不纳入本套件的范围

- 由波特率不匹配产生的比特级乱码生成过程（可用固定脏字节近似「收到了错误字节」）
- 硬件流控（RTS/CTS）
- 从机 `process` 函数体执行内部被接收中断插入新字节
- 多个主机争用同一条 UART

## 5. 完整场景表

场景编号格式为 `HS-<类别字母>-<两位序号>`。期望以第 4 节与库契约为准；个别「与实现细节绑定」的条目在在对应测试用例中固定写明具体期望字符串。

### 5.1 正常交互（N）

| ID | 场景 | 预期 |
| --- | --- | --- |
| HS-N-01 | 发送 `AT` | 得到 `OK` |
| HS-N-02 | 发送 `AT+PING` | 上行包含 `+PING:PONG`，并最终 `OK` |
| HS-N-03 | `AT+INT=42` 后再查询 | 两次最终成功；查询行值为 42；从机保存值为 42 |
| HS-N-04 | `AT+STR="hello"` 后再查询 | 最终成功；保存字符串为 `hello` |
| HS-N-05 | `AT+MIX=…` 后再查询 | 最终成功；各参数槽与实现约定一致 |
| HS-N-06 | 等待上一条 `OK` 后再发下一条 | 无错乱、无丢失应答 |

### 5.2 主机不等待 / 流水线（P）

| ID | 场景 | 预期 |
| --- | --- | --- |
| HS-P-01 | 连续发送两条 `AT`，不等待中间应答 | 最终收到两次 `OK` |
| HS-P-02 | 发送 `AT+SLOW` 后立即再发 `AT` | 最终收到两次 `OK` |
| HS-P-03 | 连续发送多条 `AT+MULTI=…` | `OK` 次数与发送条数一致；最后一次保存值正确 |
| HS-P-04 | 一次写入多个完整命令行 | 得到对应数量的最终成功应答 |

### 5.3 多行粘连与不完整帧（K）

| ID | 场景 | 预期 |
| --- | --- | --- |
| HS-K-01 | 两个完整行一次到达 | 两次 `OK` |
| HS-K-02 | 完整行与尚未结束的命令片段一次到达 | 先一次 `OK`；片段空闲超时作废再回 `ERROR` |
| HS-K-03 | 尚未结束的命令片段残留后直接发送新的 `AT\r\n` | 残留超时作废或拼成脏行回 `ERROR`，再发标准命令可 `OK` |
| HS-K-04 | 三行粘连且其中包含 `AT+PING` | 最终结果组数正确，且能观察到中间信息 |
| HS-K-05 | 未完成命令停顿超过空闲时间后再续传 | 半行空闲超时作废回 `ERROR`；后续残余无 `AT` 前缀亦回 `ERROR`，须重发完整命令 |
| HS-K-06 | 逐字节凑齐一整行 | `OK` |
| HS-K-07 | 引号包裹的参数跨多次到达（命令尚未完整） | `OK`，字符串内容正确 |
| HS-K-08 | 链路损伤处理（`link_impair`）按 1 字节切块发送整行 | `OK` |

### 5.4 行尾变体（F）

| ID | 场景 | 预期 |
| --- | --- | --- |
| HS-F-01 | `AT` 之后只有 `\r`，长时间等待 | 空闲超时后回 `ERROR`；补上孤立 `\n` 不成行，再回 `ERROR` |
| HS-F-02 | `AT` 之后只有 `\n` | 不成帧；空闲超时作废回 `ERROR`；再发标准 `AT\r\n` 应可恢复 |
| HS-F-03 | `AT\n\r` | 不成正确帧或 `ERROR`；再发 `AT\r\n` 应得 `OK` |
| HS-F-04 | `AT\r\r\n` | 与取行实现保持一致的确定结果（`OK` 或 `ERROR`，对应测试用例中固定写明） |
| HS-F-05 | `AT\r\n\r\n` | 仅一次 `OK`（额外空行不产生结果） |
| HS-F-06 | 两命令之间插入额外空行 | 两次 `OK` |
| HS-F-07 | `\r` 与 `\n` 分两次到达，中间间隔超过空闲时间 | 最终 `ERROR`（CR 半行超时作废，孤立 `\n` 不成行） |
| HS-F-08 | 只有 `\r` 之后再发另一条完整 `AT\r\n` | 脏行 `ERROR`，之后可恢复 |

| HS-S-03 | 较长时间持续发送，并穿插联通确认命令 | 不卡死；联通确认命令（如 `AT`）仍可成功 |
| HS-S-04 | 按 1 字节切块发送 20 次 PING | 20 次成功，且中间信息可观测 |
| HS-S-05 | 在连发中穿插 `AT+SLOW` | 全部命令的最终结果收齐 |
| HS-S-06 | 单次写入 16 个完整命令行 | 16 次 `OK` |

### 5.11 透传（T）

| ID | 场景 | 预期 |
| --- | --- | --- |
| HS-T-01 | `CIPMODE=1` 后无参 `CIPSEND`，数据分片到达，再以合法静默条件发送 `+++` | 提示符为 `\r\nOK\r\n>\r\n`；透传回调数据正确；退出后 `AT` 得 `OK` |
| HS-T-02 | 前静默不足时的 `+++` | 三个加号进入透传回调；之后用合法条件退出并可恢复 |
| HS-T-03 | 透传较大载荷 | 回调收到的长度匹配；能够回到命令模式 |
| HS-T-04 | 透传期间发送 `AT\r\n` 文本 | 该文本进入回调，不按命令解析；退出后命令模式恢复正常 |

### 5.12 上行方向损伤（U）

上行方向指从机→主机。`host_collect_impaired` 在主机收集侧模拟上行 EMI：每 N 字节丢 1 个并插入 1 个 `0x00` 噪声字节。

| ID | 场景 | 预期 |
| --- | --- | --- |
| HS-U-01 | 从机回 4 个应答，上行每 7 字节损伤一次 | 完整 `\r\n` 帧未被破坏的 OK 仍可识别；`OK` 计数 ≤ 4 且 ≥ 1；无凭空出现的 `ERROR`；探测 `AT` 恢复 |
| HS-U-02 | 从机回 3 个应答，上行每 5 字节丢 1 个 | 无假 `ERROR`；`OK` 计数 ≤ 3；探测 `AT` 恢复 |
| HS-U-03 | 从机回 1 个应答，上行每 3 字节重度损伤 | 主机收集不崩溃、无假 `ERROR`；探测 `AT` 恢复 |

定长 SEND / 模式切换边界的完整矩阵见 `host_slave_send`，不在此重复。

## 7. 排障备忘

下列问题在实现与调试用例时出现过，保留在此避免重复踩坑：

| 现象 | 原因说明 |
| --- | --- |
| 大量连发时 `OK` 变少或变成 `ERROR` | 空闲超时尚未到达前，主机已把大量数据写入接收缓冲；若接收缓冲过小会触发溢出丢弃接收缓冲中的全部数据。测例需为压力场景配置足够的接收缓冲。 |
| 压力场景统计到的 `OK` 偏少 | 主机侧收集应答曾过早结束；收集逻辑必须等到期望数量或明确超时。 |
| 队列满丢弃场景难以触发 | 从机线程会持续读走下行队列中的数据；需要一次写入足够大的突发，使队列在从机读走之前达到上限。 |
| 丢字节场景之后下一条合法命令仍失败 | 场景之间必须复位队列，并让从机重新初始化，避免上一场景的残留状态污染下一场景。 |
| 仅有 `\r` / 仅有 `\n`、或放弃未完成命令后的结果是 `ERROR` | 这与「只认 `\r\n` 为行尾」的契约一致，属于预期失败路径，不是实现缺陷。 |
