# async_script：从机内部时序测试

本目录用一张 **C 语言步骤表**，在可手动推进的虚拟时间轴上交错执行三类动作：向库喂入字节（模拟接收中断）、推进毫秒（触发到期的定时器回调）、调用 `lw_at_process`。目的是在不开真实双线程的前提下，复现「字节随时到达、定时器到期回调、主循环稍后再处理」这一从机内部契约。

库声明为单实例且不具备线程安全：`lw_at_feed` 允许在中断上下文调用；定时器到期回调与 `lw_at_process` 应在串行上下文中调用。本目录验证的是这些入口之间的**先后关系与时间条件**，而不是两个操作系统线程同时推进。

## 如何运行

```bash
cd lw_at/tests/system/async_script
make run
```

进程退出码为 0 表示全部检查通过。

主机与从机各占用一个线程、经模拟 UART 通信的双端测试见 `host_slave_win`（通测）与 `host_slave_send`（CIPMODE/CIPSEND 专题）。设置参数拆分的完整字符矩阵见 `lw_at_core`。

## 能力边界

| 现场情况 | 本目录的模拟方式 | 是否覆盖 |
| --- | --- | --- |
| 命令字节分多次到达 | 多次喂入，中间可夹杂短暂时间推进 | 是 |
| 完整行已到，但必须等空闲超时后才允许解析 | 先 `process`（期望无上行），再推进时间至空闲到期，再 `process` | 是（本目录重点覆盖） |
| 多个完整命令行在同一次到达中粘连、故意少喂字节、噪声行、前静默不足的假 `+++` | 在步骤表中编排对应喂入与断言 | 是 |
| `lw_at_process` 执行到函数体内部时又被中断喂入新字节 | 步骤表只能安排在 `process` 调用之前或之后喂入，无法插入函数内部 | 否 |
| 主机线程与从机线程同时运行 | 本目录始终在单线程脚本中执行 | 否；此类场景使用 `host_slave_win` |

文中若提到「丢字节」或「丢包」，含义是：**测试少喂入若干字节**，使从机从未收到这些字节；不是指网络层重传语义。

关于「`process` 执行中途被中断」：步骤表可以表达「上一行空闲已到期、即将 `process` 之前又写入下一命令的不完整片段」（例如场景 A03），但这仍发生在两次 API 调用之间，不能等价于函数执行内部的抢占。

## 场景一览

本目录使用 `fixtures` 中的测试命令（主要为 `AT`、`AT+ECHO`，以及透传相关的 `AT+CIPMODE` / `AT+CIPSEND`）。

| 编号 | 场景说明 | 预期要点 |
| --- | --- | --- |
| A01 | 将一条设置命令拆成逐字节喂入，中间夹杂短暂 `tick` | 空闲未到期时无上行；到期并 `process` 后得到 `OK` |
| A02 | 完整行已写入，但空闲时间未到就调用 `process` | 到期之前不应出现 `OK`；到期之后才出现 |
| A03 | 上一完整行已到期，在调用 `process` 之前又喂入下一命令的不完整片段 | 本次 `process` 先完成上一行；不完整片段保留待后续补齐 |
| A04 | 一次喂入两个完整命令行（同一次到达） | 一次处理得到两段 `OK` |
| A05 | `\r` 与 `\n` 分两次到达 | 仅有 `\r` 时不成行；补上 `\n` 并到期后得到 `OK` |
| A06 | 先喂入噪声字节再跟合法 `AT` | 噪声行得到 `ERROR`，随后合法命令得到 `OK` |
| A07 | 未知命令之后再发合法 `AT` | 先 `ERROR`，后仍可 `OK` |
| A08 | 设置参数中引号未闭合 | `ERROR` 之后再发合法命令可恢复 |
| A09 | 带引号的参数内容跨多次喂入（含逗号） | 最终设置成功 |
| A10 | 使用偏小的接收缓冲突发写满 | `ERROR` 之后短命令仍可成功 |
| A11 | 尚未结束的不完整行停顿一段时间后再补全行尾 | 不完整行期间不解析；补全并到期后 `OK` |
| A12 | 在无待处理数据时反复调用 `process` | 不应产生异常副作用或虚假应答 |
| A13 | 进入透传后数据分片到达，再以合法静默条件发送 `+++` 退出 | `CIPMODE=1`+无参 `CIPSEND` 得 `\r\nOK\r\n>\r\n`；数据进入透传回调；退出后命令模式的 `AT` 可得 `OK` |
| A14 | 前静默不足时发送 `+++` | 三个加号按普通数据进入回调；之后用合法静默退出并可恢复命令模式 |
| A15 | 故意少喂入命令中的某个字母 | 得到 `ERROR`，再发合法命令可 `OK` |
| A16 | 一次喂入「完整行 + 下一命令的不完整片段」 | 先得到第一行的 `OK`；补全第二行后再得到 `OK` |
| A17 | 一次喂入大量完整 `AT` 行 | 上行中 `OK` 的次数与命令条数一致 |
| A18 | 两帧合法命令之间插入噪声行 | 出现 `OK`、`ERROR`、`OK` 的顺序组合 |
| A19 | 丢掉行尾的 `\n`，使残留 `\r` 与下一帧粘连 | 先得到脏行 `ERROR`，再发标准命令可恢复 |
| A20 | 先处理积压的多行，再立刻喂入新命令 | 多段 `OK`，状态连续正确 |
| A21 | 多片写入后延迟一段时间再 `process` | 积压行被一并处理，得到对应数量的 `OK` |

## 如何扩展场景

在 `test_main.c` 中新增静态步骤数组，以约定的结束标记收尾，再在 `main` 中调用运行接口。在进行应答内容断言之前，应先清空已捕获的上行缓冲，避免与上一场景的输出混淆。
