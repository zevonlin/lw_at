# host：单线程集成测试

本目录在**同一线程**内按固定顺序调用 `lw_at_feed`、推进虚拟时间（触发定时器回调）、`lw_at_process`，对库做集成级验证。目标是用较短时间覆盖主路径：初始化、命令表注册、四种命令形态、常见非法输入、分片与多行、空闲到期后再处理、接收缓冲溢出，以及（在编译开启数据模式时）CIPMODE + CIPSEND 流式进入与退出。

本目录**不**使用操作系统线程，因此无法验证「主机线程与从机线程同时推进」的真实双端调度；通用双端见 `host_slave_win`，SEND/定长专题见 `host_slave_send`。从机内部「完整行已到、空闲尚未到期」等细粒度时序见 `async_script`。设置参数拆分的完整字符矩阵见 `lw_at_core`。

## 如何运行

```bash
cd lw_at/tests/system/host
make run
```

进程退出码为 0 表示全部检查通过。

本目录链接 `fixtures` 中的辅助实现：虚拟定时器与应答捕获缓冲区，以及测试命令表（`AT`、`AT+ECHO`、`AT+CIPMODE` / `AT+CIPSEND`，含定长与无参流式）。

## 覆盖范围

| 分组 | 说明 |
| --- | --- |
| 初始化与注册 | 校验 `lw_at_init` 的非法参数与状态约束；命令表分次注册；表内/跨表重名与重复注册应被拒绝。 |
| 四种命令形态 | 覆盖执行（裸 `AT` / `AT+ECHO`）、设置（`=`）、查询（`?`）、测试（`=?`），并核对中间信息行与保存值。 |
| 错误行与空行 | 小写 `at`、未知命令、非法设置参数、空的 `\r\n` 等；期望 `ERROR` 或无最终结果，且之后仍可恢复到合法命令。 |
| 分片与多行 | 将同一条命令拆成多次 `feed`；或一次 `feed` 写入多行完整命令，期望连续得到对应应答。 |
| 空闲时间约束 | 接收缓冲中已有完整 `\r\n` 行，但虚拟时间尚未达到 `idle_timeout_ms` 时调用 `process`，应无上行输出；推进时间并 `tick` 之后再 `process` 才应得到 `OK`。 |
| 接收缓存满 | 使用偏小的接收缓冲故意写满，期望回 `ERROR` 并丢弃当前缓存内容；之后发送短命令应仍可成功。 |
| 行超长 | 行组装缓冲过小时，超长行应回 `ERROR`，后续合法短命令应仍可成功。 |
| 流式透传（编译开启时） | `CIPMODE=1` 后无参 `CIPSEND` 回 `\r\nOK\r\n>\r\n`；进入后数据进入用户回调；合法的 `+++`（前后静默满足配置）可退出且默认不回 OK；前静默不足时的 `+++` 应视为普通数据。 |

定长 `CIPSEND=<len>` 的完整双端矩阵以 `host_slave_send` / `lw_at_core` C14 为准；本目录侧重主路径快速回归。

## 如何阅读控制台输出

用例标题以 `====` 分隔。`>>` 表示测试注入的主机下行；`<<` 表示捕获到的从机上行（其中 `\r`、`\n` 已转义显示）。每条检查打印 `[PASS]` 或 `[FAIL]`；程序结束时汇总 `checks`（总检查次数）与 `failed`（失败次数）。
