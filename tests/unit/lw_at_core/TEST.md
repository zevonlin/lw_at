# lw_at_core 模块测试

本目录对 [`lw_at_core.c`](../../../src/lw_at_core.c) 做集成级外部接口测试。链接对象包括 stream、命令字典、透传模块，以及 `fixtures` 中的虚拟定时器、应答捕获与测试命令表。数据模式（流式透传、定长窗口）恒编译覆盖。

## 如何运行

```bash
cd lw_at/tests/unit/lw_at_core
make run
```

进程退出码为 0 表示全部检查通过。

关于设置参数：如何按逗号拆成多个参数槽、如何处理省略的参数槽/引号/转义、如何用 `lw_at_get_para_digit` / `lw_at_get_para_str` 取参，**以本目录 C12 用例为完整矩阵**。其它测试目录仅抽测少量相关输入，不重复维护整张字符表。

双端 CIPMODE/CIPSEND 交互专题见 `system/host_slave_send`。

## 模块职责（测试背景）

core 是 AT 从机侧的交互总控，把各子模块串成完整命令路径：

1. **`lw_at_feed`**：把下行字节写入接收缓存后立即返回，并重载单次定时器（命令模式 arm 空闲门限，数据模式 arm guard）。允许在中断上下文调用；内部不做 AT 解析，也不调用 Port 发送。数据模式下可经 `+++` 守卫；确认退出时仅置 `exit_req`。
2. **定时器回调**：单次定时器到期由 Port 触发（等价硬件定时器 ISR）。命令模式到期置「待处理」并触发空闲通知；数据模式到期置 silent，`+++` 已凑齐时登记退出。
3. **`lw_at_process`**：仅在存在待处理数据时工作。命令模式按 `\r\n` 取行并分发 handler；按结果码回写 `OK` / `OK+>`（`\r\nOK\r\n>\r\n`）/ `ERROR`，或 `RESULT_DONE` 时不追加。数据模式：流式交付 `on_chunk`/`sink`；定长收满调 `on_done` 并回普通 `OK`，中止回 `ERROR`。
4. **帧界规则**：命令行结束符仅为 `\r\n`。空闲超时**不会**把尚未结束的不完整行当成完整行切开，只表示「可以开始处理已经完整的行」。
5. **命令形态**：裸 `AT`；执行 `AT+CMD`；查询 `AT+CMD?`；测试 `AT+CMD=?`；设置 `AT+CMD=<参数…>`。内核不内置业务命令名。
6. **接收溢出**：命令模式下接收环写满后，`process` 应回 `\r\nERROR\r\n` 并丢弃当前缓存。流式数据模式下 overflow 标志被吞掉、**不**回 ERROR（仅丢弃放不下的新字节）。
7. **数据模式**：handler 内 `lw_at_data_enter` / `lw_at_transmit_enter` 登记请求，随后 handler 同步 `lw_at_data_confirm` 切入并清空接收环；`>` 由库在回 `\r\nOK\r\n` 后补打。流式退出依赖 `+++`（前后静默由 guard 定时器回调置 silent 确认），默认不额外回 OK。定长默认不识别 `+++`（除非 `allow_plus_abort`）；`lw_at_data_exit` 可应用侧中止。

配置侧常见失误包括：接收缓冲或行缓冲过小、`idle_timeout_ms` 为 0、未注册命令、未注册流式 sink 却尝试 `transmit_enter`、设置参数槽数超过上限。字节流侧常见情况包括：分片到达、多个完整命令行粘连、尚未结束的不完整行、仅有 `\r` 或仅有 `\n`。

## 测试项一览

| 编号 | 测试项 | 测试原因 | 预期结果 |
| --- | --- | --- | --- |
| C01 | 初始化参数与状态机 | 防止未配置或重复初始化导致未定义行为 | `init(NULL)` 返回参数错误；未初始化时 `feed`/注册返回状态错误；成功 init 后再次 init 应失败 |
| C02 | 命令表注册校验 | 防止表内重名、跨表重名、同一节点重复挂链 | 表内重名与跨表重名返回参数错误；同一表节点注册两次返回状态错误 |
| C03 | 四种命令形态 | 覆盖协议主路径 | 裸 AT、设置、查询、测试、执行均得到正确最终结果；查询/测试的中间信息行内容正确；保存值与参数个数符合断言 |
| C04 | 非法行与空行 | 主机可能发送大小写错误、未知命令或畸形设置 | 小写 `at`、未知命令名、非法 query 尾缀、非法 setup、超过最大参数槽数均回 `ERROR`；单独的空 `\r\n` 不产生最终结果；之后合法 `AT` 仍可 `OK` |
| C05 | 分片喂入与多个完整命令行在同一次到达中粘连 | UART/DMA 常把一行拆成多次上报，或把多行挤在一次上报中 | 分片喂入 `AT+ECHO=5` 最终 `OK`；一次写入两行完整命令得到连续两段应答 |
| C06 | 空闲到期后再处理 | 契约要求：有完整行也必须等空闲超时后才能解析 | 有完整行但时间未到期时 `process` 无上行；到期后空闲回调触发一次，再 `process` 得到 `OK`；`feed(len=0)` 不刷新空闲，命令不会因此饿死 |
| C07 | 接收缓存写满 | 缓冲配置过小或突发过长 | 实际写入量为缓冲大小减一；`process` 回 `ERROR`；即便溢出前缓存内已有完整行，仍丢弃接收缓冲中的全部数据并回 `ERROR`；之后短命令可恢复 |
| C08 | 行组装缓冲过短 | 行缓冲配置错误 | 超长行回 `ERROR`；随后短命令仍可 `OK` |
| C09 | 流式进入、数据转发与退出 | 模式切换与作废尚未结束的不完整行 | `CIPMODE=1` 后无参 `CIPSEND` 回 `\r\nOK\r\n>\r\n`；进入后尚未结束的不完整行作废；透传数据进入用户回调；透传期间的 `AT\r\n` 不当命令解析；满足静默的 `+++` 退出后默认不回 `OK`，再发命令应按命令模式 `OK` |
| C10 | 未注册透传回调却进入流式 | 配置遗漏防护 | `CIPMODE=1` 后无参 `CIPSEND` 回 `ERROR`，仍停留在命令模式 |
| C11 | `+++` 前后静默不足或序列被破坏 | 避免把普通数据中的加号误判为退出 | 静默不足或序列中途出现非 `+` 时，相关字节按普通数据转发；满足条件退出后再发 `AT` 应得 `OK`；feed 退出前残留透传数据须先交 sink |
| C12 | 设置参数拆分与取参 | 按逗号拆分为参数槽、省略参数槽、引号、转义与边界错误 | 见下表 C12.1–C12.9；非法输入路径不得调用 setup handler |
| C13 | 流式退出加固 | 空 feed / 仅 process 路径 | 凑齐 `+++` 后若不触发定时器，`feed(len=0)` 不得确认退出，随后同刻数据应把 `+++` 还原进 sink；`feed` 置待退出后仅 `process`（定时器回调已完成）也应排空残留并切回命令模式，随后空闲处理可得 `AT` 的 `OK` |
| C14 | 定长数据窗口 | 类 CIPSEND：OK 后再单独一行 `>` | `AT+CIPSEND=5` 回 `\r\nOK\r\n>\r\n`；分片喂入收满后回调得到正文与 `got==5`，主机见普通 `\r\nOK\r\n`；随后 `AT` 仍为命令模式 `OK`；`AT+CIPSEND=0` 回 `ERROR` |

### C12 设置参数字符矩阵

下列输入均针对设置命令的参数区（等号之后、行结束符之前）。「空的参数槽」表示该位置两个逗号之间没有正文，取参接口应报告「省略」。

| 子项 | 输入要点 | 预期 |
| --- | --- | --- |
| C12.1 | `115200,8,1` | 得到三个非空参数槽；按整数读取各槽数值正确 |
| C12.2 | `AT+SLOT=`（等号后无正文） | 视为一个空的参数槽（省略） |
| C12.3 | `,`、`,,`、`,a`、`a,`、`a,,b` | 空的参数槽与非空参数槽的位置、个数与正文一致 |
| C12.4 | `""`；带引号的多槽；引号内包含逗号 | 去掉包围引号；引号内的逗号不作为参数分隔符 |
| C12.5 | 引号内外的 `\,`、`\\`、`\"` 以及未定义转义 | 按库约定还原或保留；测例断言与实现一致 |
| C12.6 | 槽正文中嵌套引号、花括号等 | 该槽取出的字符串完整保留这些字符 |
| C12.7 | `"42"`、`12a`；以及 `AT+ECHO="42"` | 纯数字引号串可按整数成功；含非数字字符的串按整数失败；ECHO 设置可保存 42 |
| C12.8 | 未闭合引号、行尾孤立反斜杠、超过最大槽数 | 回 `ERROR`，且 setup 调用次数不增加 |
| C12.9 | 恰好等于最大允许槽数 | 回 `OK`，`para_num` 等于上限 |

## 如何阅读控制台输出

- `====`：用例分组标题
- `>>`：主机下行（测试注入）
- `<<`：从机上行（捕获缓冲；不可见字符已转义）
- `sink`：流式数据模式下用户回调捕获到的数据
- `[PASS]` / `[FAIL]`：单条检查结果；程序结束打印 `checks` 与 `failed`
