# lw_at_stream 模块测试

本目录对 [`lw_at_stream.c`](../../../src/lw_at_stream.c) 做单元测试，**不**链接 core、命令字典或透传模块。验证范围限于接收环形缓冲区、取行、溢出与待处理/满丢弃标志本身。空闲定时已改为事件驱动（单次定时器到期回调置 pending），不属本模块职责；上层组合见 `lw_at_core`、`async_script` 等目录。

## 如何运行

```bash
cd lw_at/tests/unit/lw_at_stream
make run
```

进程退出码为 0 表示全部检查通过。

## 模块职责（测试背景）

在 AT 从机路径中，stream 负责字节进入与行边界识别：

1. 把主机侧任意长度的字节片段写入接收环形缓冲区（对应 `lw_at_feed` 的底层实现）。
2. **仅**以连续的 `\r\n` 作为一行结束。本模块不感知空闲；尚未以 `\r\n` 结束的数据保留在缓存中，直到补齐行尾或被上层 `reset`（上层 core 在空闲超时后作废残留并回 `ERROR`，见 `lw_at_core` / `async_script`）。
3. 环形缓冲区无法再写入时，丢弃本次未能写入的新字节，并置位溢出标志；是否向主机回 `ERROR`、是否清空整段缓存，由上层 core 决定。
4. 「待处理」标志由上层定时器回调置起，`pending_take` 一次性取走。

配置侧常见问题：接收缓冲过小、上层提供的行输出区过短。字节流侧常见问题：逐字节分片、任意长度分片、尚未结束的不完整行、只有 `\r`、只有 `\n`、空行、一次写入多行、环形缓冲区回绕、溢出后缓存内仍残留完整行。

## 测试项一览

| 编号 | 测试项 | 测试原因 | 预期结果 |
| --- | --- | --- | --- |
| S01 | 初始化后缓存为空 | 确认上电/init 后的干净状态 | 可读长度为 0；取行返回无行；溢出与待处理标志读出为 0 |
| S02 | 整行一次写入并可取出 | 正常命令行路径 | 取出的正文等于写入内容且不含 `\r\n`；再次取行得到无行 |
| S03 | 逐字节分片组帧 | UART 常按单字节中断上报 | 依次写入 `A`、`T`、`\r`、`\n` 后，仍取出正文 `AT` |
| S04 | 任意长度分片组帧 | 驱动一次上报的长度不确定 | 多片拼成一行后取出完整正文 |
| S05 | 尚未结束的不完整行（尚未出现 `\r\n`） | 命令仍在发送中 | 取行返回无行；已写入字节仍保留在缓存中 |
| S06 | 只有 `\r`、没有 `\n` | 行尾不完整或主机只发了 CR | 不构成完整行，取行返回无行 |
| S07 | 只有 `\n`、前面没有 `\r` | 误把 LF 当作行结束 | 不构成完整行（协议要求顺序为 `\r\n`） |
| S08 | 空行 `\r\n` | 主机多按回车 | 取出长度为 0 的一行正文 |
| S09 | 一次写入包含多行 | 一次写入中含多个完整行 | 可连续多次取行，依次得到各行正文 |
| S10 | 行长度超过输出区 | 模拟上层 `line_buf` 过小 | 返回行过长；该行从环形缓冲区中被消费掉；后续完整短行仍可取出 |
| S11 | 环形缓冲区回绕后再取行 | 读写指针跨越物理缓冲末尾 | 先填满再消费一部分后再写入，仍能正确取出完整行 |
| S12 | 环形缓冲区写满 | 缓冲配置过小或突发过长 | 实际写入字节数为容量减一；溢出标志置位；未能写入的字节被丢弃 |
| S13 | 溢出之后缓存内仍有完整行 | 满丢弃策略下的残留数据 | 本模块仍允许取出该完整行；溢出标志可被读取一次；是否丢弃接收缓冲中的全部数据由上层决定 |
| S14 | `reset` 清空未读数据 | 进入透传前作废尚未结束的不完整行等场景 | 清空后可读长度为 0，取行返回无行 |
| S15 | 回绕场景下的分段 peek/consume | 透传零拷贝转发需要按物理连续段读取 | 第一次 peek 只返回到物理末尾的连续段；consume 之后再 peek 得到剩余部分 |
| S16 | `pending` 标志一次性语义 | 空闲判定已改为事件驱动：定时器回调置 pending，process 消费 | 直接置位后 `pending_take` 返回 1 且再次取为 0 |
| S17 | 读取溢出标志具有一次性语义 | 标志被消费后应清零 | 第一次读出为 1，紧接着再读为 0 |

## 与上层的职责边界

- **关于 S13**：stream 在溢出后**不会**自动丢弃环形缓冲区中已经存在的数据。把「溢出则丢弃接收缓冲中的全部数据并回 `ERROR`」做成产品行为的是 core 的 `lw_at_process`。本目录只验证溢出标志与取行接口本身。
- **关于空闲与行结束条件**：本模块取行仅以 `\r\n` 为界，不感知空闲；尚未结束的不完整行或「只有 `\r`」在已经空闲的情况下，取行仍返回无行。产品层面空闲超时后由上层 core 作废残留并回 `ERROR`。

## 如何阅读控制台输出

每个用例打印标题、`>>`（操作说明或喂入的转义字节）、`<<`（返回值、取出正文、标志位）、以及 `[PASS]` / `[FAIL]`。程序结束时汇总 `checks` 与 `failed`。
