# lw_at_transmit 模块测试

本目录对 [`lw_at_transmit.c`](../../../src/lw_at_transmit.c) 做单元测试。会链接 `lw_at_stream.c`。透传模块恒编译。

整机层面的「命令模式 / 数据模式」切换、定长窗口，以及主机与从机两端的交互，分别见 `lw_at_core`（C09–C14）、`async_script`、`host_slave_win` 与 `host_slave_send`。

## 如何运行

```bash
cd lw_at/tests/unit/lw_at_transmit
make run
```

进程退出码为 0 表示全部检查通过。

## 模块职责（测试背景）

透传模块处理「已经进入**流式**数据模式之后」的字节路径，本身**不**负责把工作模式从命令模式切入（那一步由 core 在命令 handler 请求进入并回完 `OK` 之后完成）。本模块关注：

1. **普通数据**：写入接收流，由上层 `process` 转交给用户注册的透传数据回调。
2. **退出序列 `+++`**：前后静默约束改由 **silent 标志**事件驱动——出现第一个 `+` 之前须前静默满足（silent=1）；三个 `+` 收齐之后，再经 guard 定时器到期置 silent 后，下一段数据到达时确认退出（silent=1）。silent 由上层在 guard 定时器到期时置位。
3. **候选暂存与还原**：正在识别退出序列时，已收到的 `+` 先暂存、不进入数据流。若序列被破坏（中途出现非 `+`，或同一段数据在凑齐 `+++` 后又附带其它字节，或后静默不足就被新数据打断），则把已暂存的 `+` 按普通数据写回接收流。
4. **溢出策略**：透传下接收环形缓冲区满时只丢弃无法写入的数据并清除溢出标志，**不**像命令模式那样回 `ERROR` 行。

字节流侧常见情况包括：`+++` 被拆成多次到达、同一包内 `+++` 后面还跟着其它字节、`+` 出现在普通数据段的中间而不是段首、前静默或后静默不足、将 guard 关闭（silent 恒满足）。

## 测试项一览

| 编号 | 测试项 | 测试原因 | 预期结果 |
| --- | --- | --- | --- |
| T01 | 初始化 | 确认初始状态干净 | 未处于「正在凑 `+`」 |
| T02 | `reset` | 清理解析暂存 | 凑 `+` 的计数清零 |
| T03 | 普通数据写入 | 非退出路径 | 数据可从流中 peek 到；未报告退出 |
| T04 | 前静默不足时出现 `+` | 避免把紧跟数据的加号误当作退出序列起点 | 该 `+` 作为普通数据进入接收流 |
| T05 | 前静默满足（silent=1），且本段数据以 `+` 开头 | 正确进入退出序列识别 | 该 `+` 被暂存，不出现在接收流中；内部计数为 1 |
| T06 | 已累计两个 `+`，尚未满三个 | 序列未完成 | 仍未退出 |
| T07 | 凑齐三个 `+` 后，下一段数据 silent=1 | 数据路径确认退出 | 报告退出且本段不入接收流（返回 0）；由上层记下分界后再写入 |
| T08 | 凑齐三个 `+` 后，后静默尚未满足就来了新数据 | 后静默不足应撤销退出候选 | 不报告退出；三个 `+` 被还原写入接收流 |
| T09 | 序列中途出现非 `+`（例如先 `++` 再 `A`） | 序列破坏 | 已暂存的 `+` 与后续的 `A` 都进入接收流；计数清零 |
| T10 | `+` 不是本段数据的第一个字节 | 段中间的加号不是退出序列起点 | 不进入识别状态，整段数据进入接收流 |
| T11 | 同一段数据内已经凑齐 `+++`，后面还紧跟其它字节 | 例如一包 `+++A` | 视为破坏；整段（含三个 `+` 与后续字节）进入接收流 |
| T12 | 关闭守卫（silent 恒满足） | 无需等待间隔即可识别并退出 | 凑齐 `+++` 后下一段 silent=1 即退出 |
| T13 | 三次 `feed` 各写入一个 `+` | UART 分片到达 | 三次之后凑齐，再一段 silent=1 确认退出 |
| T14 | `process` 将流中数据转给回调 | 透传下行转发 | 回调收到全部字节；流中数据被全部读出；溢出标志被清除 |

## 与上层的职责边界

本模块通过返回值/输出参数告诉上层「是否应当退出透传」，**不**自行修改 core 的工作模式，也不负责退出后的命令解析。模式切换、作废尚未结束的不完整行，以及退出后读空接收流，由 core 完成。静默时长的计时与 silent 置位由上层 guard 定时器回调负责。
