# BUG-001：`+++` 跨段累积可退出（误触发风险）

## 追踪信息

| 项 | 值 |
| --- | --- |
| Bug ID | BUG-001 |
| 标题 | `+++` 跨段累积可退出（误触发风险） |
| 状态 | 已修复 |
| 优先级 | 中 |
| 修复版本 | lw_at v1.14.0 |
| Git 提交 | 待提交 |
| 发现日期 | 2026-08-11 |
| 修复日期 | 2026-08-11 |
| 发现来源 | 数据模式/透传切换闭环测试补测（P1-P4） |
| 修复方式 | 静默超时时清零未凑齐的 `+` 暂存（`at_timer_expired`） |

## 现象

在 STREAM 流式数据模式下，**跨时间间隔分发的 `+` 能累积成 `+++` 并触发退出**：

- 先发一个 `+`，隔 1 秒（甚至十几秒）再发 `++`，只要前后静默满足，**仍能退出数据模式**。
- 实测（补测 P1/P2）：`+` → 1s → `++` 成功退出回命令模式并回 `OK`。

## 根因

`lw_at_transmit.c` 的 `lw_at_transmit_feed` 中，透传状态 `plus_cnt`（已暂存的 `+` 个数）**跨 feed 段保留且无超时失效**：

```c
if (tm->plus_cnt == 0U) {
    /* 候选序列只能由「前静默后本段首字节的 '+'」开启 */
    if ((b == (uint8_t)'+') && (i == 0U) && (silent != 0U)) {
        tm->plus_cnt = 1U;   /* 开始暂存 +，但不随静默超时清零 */
```

只要段间静默满足（guard_ms=100ms），`plus_cnt` 持续累积，跨长时间拼出 `+++` 也能触发退出。

## 协议角度分析

**该行为不符合"退出序列"的协议语义**：

| 协议本意 | 当前缺陷行为 |
| --- | --- |
| `+++` 是一次性连续三字节的退出信号 | 离散输入跨时间拼凑也能退出 |
| 退出信号须可靠区别于数据 | 数据中碰巧出现的 `+` 可能被跨时间拼成退出信号 |
| 行为确定、可预期 | 主控无退出意图时可能被意外踢出数据模式 |

对比业界惯例（ESP-AT 等）：`+++` 退出均为**一次性连续三字节**，不要求跨时间累积。

**误触发反例**：数据模式下主控发了 `"temp++"`（两个 `+` 被暂存），3 分钟后又发 `"+end"` → 模块误判 `+++` 退出，数据通道被意外打断。

## 复现步骤

1. 进入 STREAM 数据模式（`AT+BLESNTFY=0,3,2` → OK + `>`）
2. 发 `+`（hex `2B`），等待 1 秒
3. 发 `++`（hex `2B2B`），等待 1 秒
4. 模块退出数据模式并回 `\r\nOK\r\n`

## 修复方向（二选一，待定）

1. **静默超时清 `plus_cnt`**（推荐）：`+` 段间隔超过 guard_ms 时，之前暂存的 `+` 作废，累积失效。
2. **要求同段连续**：`+++` 必须在同一次 feed 段内连续出现，跨段不累积。

## 相关测试

- 补测 P1：`+` → 1s → `++` → 静默 → **退出**（证明缺陷）
- 补测 P2：`++` → 1s → `+` → 静默 → **退出**（证明缺陷）
- 补测 P3/P4：中途非 `+` 数据破坏累积 → 不退出（正常）

## 相关文档差异

- `at_command_set.md` 6.1.2 静默时间写 `20ms`，实现 guard_ms 为 `100ms`（待对齐）。
- 6.1.2 "三个 `+` 之间至多 20ms 无输入"表述与跨段累积行为不符（应明确 `+++` 连续、跨段作废）。
- 暂存 `+` 挂账行为：`plus_cnt < 3` 时暂存的 `+` 不透传、不退出，需后续数据触发还原（可能被主控误判为丢数据）。

## 修复记录（2026-08-11）

**修复内容**：`lw_at_core.c` 的 `at_timer_expired` 数据模式分支，静默超时时将**未凑齐 `+++` 的暂存 `+` 清零**：

```c
if (at->transmit.plus_cnt == LW_AT_PLUS_SEQ_LEN) {
    /* 已凑齐：登记退出（既有逻辑） */
    at->exit_req  = 1U;
    at->transmit.plus_cnt = 0U;
} else if (at->transmit.plus_cnt != 0U) {
    /* 未凑齐：静默超时，暂存 '+' 作废（BUG-001 修复） */
    at->transmit.plus_cnt = 0U;
}
```

**效果**：
- 跨静默（>guard_ms）分发的 `+` 无法累积成 `+++`，不再误触发退出。
- 同段连续 `+++` 正常退出（`plus_cnt==3` 走既有退出分支，不受影响）。

**附带新增**：`lw_at_guard_get()` / `lw_at_guard_set(ms)` 运行期 API，可配置默认静默间隔（默认 100ms），单次会话可用 `lw_at_data_enter_cfg_t::guard_ms` 覆盖。

**验证**：需重测 P1（`+`→1s→`++` 应不退出）+ S3（静默→`+++`→静默 应正常退出）。
